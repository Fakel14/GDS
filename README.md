# GDS — Geometry Dash Songs

Демонстрационный маркетплейс музыки, ремиксов и скаутинга для сообщества Geometry Dash.

## Запуск на Windows

Установите Node.js LTS. В терминале в папке проекта выполните:

```bash
npm install
npm run dev
```

Откройте адрес Vite из терминала (обычно http://localhost:5173). Команда запускает и сайт, и сервер аккаунтов. Для остановки нажмите Ctrl+C. `npm run build` собирает сайт, а `npm start` запускает сервер с готовой сборкой на порту 3001.

## Заявка и аккаунт

1. Пользователь заполняет никнейм, профиль Newgrounds и контакт. Никнейм — от 3 до 30 букв, цифр, символов `_` или `-`.
2. Сайт подготавливает текст заявки. **Пользователь сам копирует и отправляет его в личные сообщения аккаунту fakelo4ik на Newgrounds.** Сайт не отправляет сообщения автоматически и не получает подтверждения доставки.
3. Администратор вручную проверяет профиль и наличие вайтлиста Geometry Dash. После одобрения он на сервере GDS, где запущен сайт, выполняет:

   ```bash
   npm run account:create -- "Никнейм"
   ```

   Ник должен точно соответствовать заявке. Команда выдаст ID и случайный секретный код **один раз**. Администратор передаёт их пользователю лично, например в ответ через Newgrounds. Не публикуйте код. Никакие письма автоматически не отправляются.
4. Пользователь входит с ID и кодом; ник изменить нельзя. Удаление аккаунта требует повторного ввода кода. Без входа создание объявления недоступно.

Имена уникальны без учёта регистра и Unicode-нормализации; визуально похожие символы из разных алфавитов могут отличаться. Аккаунты хранятся в `data/accounts.json` на том компьютере, где работает сервер; в Git этот файл не попадает. Код хранится только в виде хеша. Администратору нужно делать защищённые резервные копии данных. При перезапуске сервера активные сессии завершаются. Локальный сервер каждого пользователя не разделяет аккаунты с другими: для общего доступа нужен один развёрнутый сервер с постоянным хранилищем. Для HTTPS установите `COOKIE_SECURE=true`. Не выкладывайте папку `data` в открытый доступ. Эта простая реализация предназначена для тестирования, перед публичным запуском необходимы аудит безопасности, защищённое развёртывание, резервирование и более надёжное хранилище/ограничение запросов.

## Аккаунт администратора

Для безопасности права не выдаются просто по никнейму. Создайте собственный аккаунт `Fakelo4ik` через `npm run account:create -- "Fakelo4ik"` (если его ещё нет), сохраните ID и код. Затем в другом терминале в папке проекта на том же сервере выполните:

```bash
npm run account:admin -- "ID-аккаунта-Fakelo4ik"
```

Команда принимает только ID существующего аккаунта с ником Fakelo4ik. Выйдите и войдите снова, если уже вошли: появится вкладка «Заявки». Команду может выполнить только человек с доступом к серверу; не выдавайте эту роль чужому аккаунту. Удаление аккаунта администратора через сайт заблокировано.

## Объявления и модерация

Объявления теперь сохраняются на сервере в `data/listings.json` и видны всем посетителям после одобрения. Администратор может открыть вкладку «Заявки», одобрить, отклонить или исправить объявление. При изменении опубликованного объявления владельцем оно снова скрывается до проверки. Отклонённую заявку можно исправить и отправить повторно. Лимит — три опубликованных или ожидающих проверки объявления на пользователя в каждой категории; отклонённые не учитываются. Все права и лимиты проверяются сервером.

Профиль открывается по нажатию на ник автора или через кнопку «Найти автора». В своём профиле можно изменить или удалить объявления. Администратор может редактировать и удалять чужие объявления и удалять чужие аккаунты вместе с их объявлениями. Удаление собственного аккаунта также удаляет его объявления. Старые локальные черновики предыдущей версии не переносятся автоматически и остаются в localStorage браузера; они не опубликованы.

## Ограничения прототипа

Избранное хранится в браузере. Заявки на регистрацию по-прежнему отправляются пользователем вручную через Newgrounds; автоматической проверки вайтлиста, оплаты и сообщений на сайте нет. Не сообщайте Newgrounds-пароль или код GDS в заявке. JSON-хранилище рассчитано на один процесс сервера, не на масштабирование; регулярно создавайте защищённые копии папки `data`. Если аварийное завершение оставило файл `data/accounts.lock`, удалять его можно только после остановки всех серверов и команд управления аккаунтами. Перед публичным запуском необходим аудит безопасности и надёжная база данных.
